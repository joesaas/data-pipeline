# 富详情页定时任务（Muse 侧，待 API 上线后启用）

> 本文件只写任务口径，不创建任务本身。API 端点见 README「富详情页」一节。
> 任务必须在 data-pipeline 新接口部署上线后再启用，否则拉列表会 404。

## 输入

- 待生成列表：`GET {DATA_PIPELINE_BASE_URL}/api/v1/news-detail/pending?limit=10`
  （鉴权开启时带 `X-API-Key`；一次最多 10 条，按清洗时间从旧到新）
- UI 模板：三标签单页结构——新闻原文 / 大白话 / AI解读。
  模板参考：生产版 Vertalo 详情页（新闻原文一字不动，两个解读标签顶部各留一句
  “事实以新闻原文为准”的提示；解读中引用的数字必须来自新闻原文链接的来源，
  来源未说明的标“尚未确认”，不编答案）。
- 每条的原新闻地址：列表返回的 `original_url`，即原 `news/item/<id>/` 地址，
  任务用它取新闻原文；该地址本身的逻辑保留，不被新详情页替换。
- 原文地址栏口径：详情页里展示的“原文地址”/“来源”链接，只能是条目 `sources`
  里的外部链接（域名不是 `agent101.uk` 的）；`original_url` 是本站
  `news/item/<id>/` 地址，只用来取原文核对，绝不作为原文地址渲染；
  条目无外部来源时，原文地址整行不渲染（留空），不得用本站地址占位。

## 每条的处理步骤

1. 从待生成列表取一条，打开 `original_url` 核对标题、摘要、细节、来源。
2. 按模板生成一个完整的单页 HTML 文件（零外部依赖，样式内联在文件里，
   与模板同一套视觉 token；标签可点击切换，支持键盘左右切换与 `#` 锚点）。
3. 推回 API：`POST {DATA_PIPELINE_BASE_URL}/api/v1/news-detail/pages`
   body：`{ "item_id": "<cleaned item id>", "html": "<完整 HTML>" }`
   （不填 `detail_path` 时服务端默认用 `<item_id>.html`）。
4. 成功（201 新建 / 200 重推）后该条自动从下一轮待生成列表消失；
   失败（非 2xx）时不写状态，下一轮仍会拉到同一条，可重试。
   生成失败本身不调用 push 接口，条目保持待生成状态。

## 不做的事

- 不改、不删原 `news/item/<id>/` 页面与 exporter 的输出。
- 不把模板里的 Vertalo 示例文字硬编码进其他新闻的页面。
- 不把本站 `news/item/<id>/` 地址渲染成详情页的“原文地址”。
- 不绕过 push 接口直接往 `NEWS_DETAIL_DIR` 写文件：文件与状态必须
  由同一接口成对写下，否则列表与磁盘会不一致。

## 上线前检查清单

- [ ] data-pipeline 新接口已推远端并在 EC2 部署（`./deploy.sh deploy` 后
      `GET /api/v1/news-detail/pending` 返回 200，而不是 404）
- [ ] EC2 上 `NEWS_DETAIL_DIR` 目录存在且 API 进程可写
- [ ] 用一条真实新闻走通“拉列表 → 生成 → push → 再拉列表该条消失”
      的全链路后，再把任务设为定时运行
